- **Status**: TODO

## Problem

The four macro bars are the centrepiece of this app — they are the first thing on
the Home screen (`src/pages/Home.tsx:211-218`) and the entire point of logging a
meal. They currently **teleport**:

```tsx
// src/components/MacroSummary.tsx:40-42 — current
<div className="mt-2 h-2.5 overflow-hidden rounded-full bg-neutral-100">
  <div className={`h-full rounded-full ${item.color}`} style={{ width: `${progress}%` }} />
</div>
```

```tsx
// src/pages/Home.tsx:458-460 — current, the same pattern in AskBar
<div className="mt-1 h-2 overflow-hidden rounded-full bg-neutral-100">
  <div className={`h-full rounded-full ${color}`} style={{ width: `${progress}%` }} />
</div>
```

No transition on either. Every state change snaps instantly:

- logging a meal (`src/pages/Home.tsx:80-83` → `refresh()`) jumps all four bars
- tapping an entry swaps the chart to that entry's macros
  (`src/pages/Home.tsx:71-72`, `selectEntry` at `:200`) — all four bars jump
- clearing the selection jumps them all back

This is the single clearest case in the app of AUDIT category 8: a state change
that teleports where a brief transition would explain what changed. Logging a
meal is the app's core reward moment, and right now the number and the bar both
just appear at their new values with nothing connecting them to the old ones.

There is a second, smaller problem: `width` is a layout-triggering property.
Animating it would force layout + paint + composite on every frame. `transform`
is the correct property (AUDIT category 5).

## Target

Drive the fill with `scaleX` from a left origin, transitioned over 300ms with the
strong ease-out curve:

```tsx
/* target — src/components/MacroSummary.tsx */
<div className="mt-2 h-2.5 overflow-hidden rounded-full bg-neutral-100">
  <div
    className={`h-full w-full origin-left rounded-full ${item.color} transition-transform duration-300 ease-strong`}
    style={{ transform: `scaleX(${progress / 100})` }}
  />
</div>
```

```tsx
/* target — src/pages/Home.tsx, AskBar */
<div className="mt-1 h-2 overflow-hidden rounded-full bg-neutral-100">
  <div
    className={`h-full w-full origin-left rounded-full ${color} transition-transform duration-300 ease-strong`}
    style={{ transform: `scaleX(${progress / 100})` }}
  />
</div>
```

Three things changed per bar: `width: N%` became `w-full` +
`transform: scaleX(N/100)`; `origin-left` makes it grow from the left edge
rather than the centre; `transition-transform duration-300 ease-strong` animates
it. `ease-strong` is the Tailwind utility generated by the `--ease-strong` token
from plan 001.

### Two things the executor must NOT "fix"

1. **`scaleX(0)` at zero progress is correct here.** AUDIT's "never `scale(0)`"
   rule is about elements *appearing from nothing*. A progress bar at 0% is an
   empty bar, not an entrance animation. Leave it.
2. **The rounded right cap will squash slightly.** Today `rounded-full` on the
   inner div gives a partial bar a rounded right end. Under `scaleX(0.5)` a 5px
   radius renders as 2.5px horizontally. At `h-2.5` (10px tall) this is a subtle
   flattening, and it is the accepted cost of animating on the compositor
   instead of thrashing layout. Keep `rounded-full` — the parent's
   `overflow-hidden rounded-full` still clips the left cap cleanly. If the
   squash turns out to be objectionable on device, the fallback is
   `transition-[width] duration-300 ease-strong` with `width` retained; note it
   in your report rather than switching unilaterally.

### Reduced motion

Plan 001's global baseline already reduces these transitions to ~0ms under
`prefers-reduced-motion: reduce`, which is the right outcome for a bar whose
final position carries all the meaning. No `motion-reduce:` variant is needed
here.

  today's totals, `AskBar` for a hypothetical addition). Keep them in sync — the
  same class string, the same duration, the same curve. Do **not** extract a

- Colours arrive as Tailwind class strings via props (`color: 'bg-amber-500'` at

  `className` template exactly as now.
- `progress` is already computed and clamped 0-100 at
  `src/components/MacroSummary.tsx:31` and `src/pages/Home.tsx:448`. Reuse those
  values; do not change the clamping maths.
